### 🔴 Bug T4 — `initializeNewUser` ném 404 cho user có subscription EXPIRED/CANCELLED

**File:** `backend/src/main/java/com/cramer/service/implement/SubscriptionServiceImpl.java:189-222`

**Lịch sử:** Introduce bởi commit `aa251f5b` (15/12/2025, Cramer Dev) — "Overhaul subscription quota system"

**Mô tả bug:**
```java
// Line 192-198
if (subscriptionRepository.existsByUserId(userId)) {
    return subscriptionRepository.findActiveByUserId(userId)
            .map(UserSubscriptionDTO::fromEntity)
            .orElseThrow(() -> new ResourceNotFoundException("UserSubscription", "userId", userId));
}
```

- `existsByUserId` check tồn tại record bất kỳ
- `findActiveByUserId` chỉ trả record có `status = ACTIVE` AND `(expires_at IS NULL OR expires_at > now)`
- Nếu user có sub EXPIRED → `existsByUserId=true`, `findActiveByUserId=empty` → **throw `ResourceNotFoundException` → 404**

**Kịch bản trigger:**
- User mua Cramerich → record `status=ACTIVE`, `expires_at=2025-01-01`
- Hôm nay 23/04/2026 → expired
- User click "Gói đăng ký" → trang crash với "Subscription not found"

**Tác động:** 🔴 **CRITICAL — paying customer không vào được trang quản lý subscription để renew/upgrade**

#### 🔬 Nghiên cứu sâu T4 (bổ sung 23/04/2026)

##### Chain dẫn đến 404 (full trace)

```
User Cramerich expired (status='ACTIVE', expires_at < now)
   ↓
GET /api/subscriptions/my-status → SubscriptionServiceImpl.getSubscriptionStatus (L272)
   ↓ findActiveByUserId() (filter expires_at > now) → empty
```

##### Yêu cầu nghiệp vụ cần đảm bảo khi fix

1. **Paying user expire xong vẫn vào được trang Subscription** để xem lịch sử & nhấn Renew/Upgrade
2. **Auto-downgrade về free tier** sau khi gói trả phí hết hạn (chuẩn SaaS — Spotify, ChatGPT, Notion)
3. **Giữ nguyên Lúa & vocabulary** đã có (KHÔNG reset balance khi downgrade)
4. **KHÔNG cấp lại `initialLua` bonus** khi downgrade (tránh exploit: mua → expire → free Lúa lần nữa)
5. **Hiển thị "previous plan"** trong UI ("Gói Cramerich đã hết hạn ngày X — Gia hạn?")
6. **DB state phải nhất quán**: ACTIVE row hết hạn phải được flip → EXPIRED (cho admin reporting/analytics)
7. **Idempotent**: API gọi nhiều lần (StrictMode, retry) không tạo row spam
8. **Renewal/Upgrade tái sử dụng row free hiện tại** (UPDATE) thay vì tạo row mới mỗi lần thanh toán

##### Đề xuất fix — 4 layers

###### Layer A (CORE — bắt buộc) — `initializeNewUser` không bao giờ throw

```java
@Override
@Transactional
public UserSubscriptionDTO initializeNewUser(UUID userId) {
    logger.info("🆕 Ensuring active subscription for user: {}", userId);

    // 1. Idempotent: đã có active → return ngay
    Optional<UserSubscription> activeOpt = subscriptionRepository.findActiveByUserId(userId);
    if (activeOpt.isPresent()) {
        return UserSubscriptionDTO.fromEntity(activeOpt.get());
    }

    // 2. Flip stale ACTIVE rows (expires_at < now) → EXPIRED để DB nhất quán
    expireStaleActiveRows(userId);

    // 3. Tạo free tier row mới (auto-downgrade)
    SubscriptionTier freeTier = tierRepository.findFreeTier()
            .orElseThrow(() -> new ResourceNotFoundException("SubscriptionTier", "code", FREE_TIER_CODE));

    UserSubscription subscription = UserSubscription.builder()
            .userId(userId)
            .tier(freeTier)
            .status(UserSubscription.Status.ACTIVE)
            .attemptAisUsed(0)
            .attemptsUsed(0)
            .chatbotUsed(0)
            .autoRenew(false)
            // expiresAt = null → lifetime free tier
            .build();
    subscription = subscriptionRepository.save(subscription);

    // 4. Chỉ cấp initialLua nếu user CHƯA TỪNG có credit record (first-time)
    //    Tránh exploit: mua → expire → nhận initial bonus lần 2
    boolean firstTimeUser = creditRepository.findByUserId(userId).isEmpty();
    if (firstTimeUser && freeTier.getInitialLua() != null && freeTier.getInitialLua() > 0) {
        creditService.initializeCredits(userId, freeTier.getInitialLua());
        logger.info("🎁 Granted initial Lúa to first-time user {}", userId);
    } else {
        logger.info("⬇️ Auto-downgraded user {} to free tier (no Lúa bonus — not first time)", userId);
    }

    return UserSubscriptionDTO.fromEntity(subscription);
}

private void expireStaleActiveRows(UUID userId) {
    OffsetDateTime now = OffsetDateTime.now();
    List<UserSubscription> all = subscriptionRepository.findByUserIdOrderByStartedAtDesc(userId);
    for (UserSubscription sub : all) {
        if (sub.getStatus() == UserSubscription.Status.ACTIVE
                && sub.getExpiresAt() != null
                && sub.getExpiresAt().isBefore(now)) {
            sub.setStatus(UserSubscription.Status.EXPIRED);
            subscriptionRepository.save(sub);
            logger.info("⏰ Auto-expired subscription id={} for user {} (was {})",
                    sub.getId(), userId, sub.getTier().getCode());
        }
    }
}
```

Đồng thời simplify `getSubscriptionStatus` (L272-288) — bỏ `throw ResourceNotFoundException` ở L287 (sau Layer A không bao giờ reach):

### 🔴 Bug S1 — `boolean isFree` Jackson serialize sai key

**File:** `backend/src/main/java/com/cramer/dto/SubscriptionStatusDTO.java:66`

**Lịch sử:** Introduce bởi commit `4b73b7c0` (14/12/2025, Cramer Dev)

**Mô tả bug:**
